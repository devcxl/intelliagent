# ADR 0008: 默认安全姿态——不捆绑 permission 插件

## 状态

已决策（用户显式否决了"捆绑默认启用的 permission 插件"方案）。

## 背景

重构后 permission 由插件能力提供（ADR 0007）。存在一个必须回答的问题：用户没有安装任何 permission 插件时，内核对 bash/edit/write 等破坏性工具的默认行为是什么？

## 决策

**发行版不捆绑 permission 插件**。无 permission 插件时内核不做任何检查，所有注册工具直接放行。permission 插件由社区提供，用户按需安装。

## 被否决的方案

- **内核硬编码不可关闭的安全底线**（破坏性工具默认 ask）：与"能力缺席即功能缺席"的插件哲学冲突，用户明确选择最大可插拔性。
- **捆绑 permission 插件但默认启用**：被视为对同一哲学的妥协，不采纳。
- **捆绑但默认关闭**：仍有发行版兜底，不如干脆不捆绑。

## 后果

- **默认安装是一个无确认、无审计的 shell 执行器**，模型可直接执行任意 bash。这与通用的 "security on by default" 实践相反，是为最大可插拔性做出的有意取舍。
- 用户文档必须显著提示：面向不可信任务使用时应先安装 permission 插件。
- 安全审计或生产化使用前，需重新评估此决策（可由后续 ADR 推翻）。
