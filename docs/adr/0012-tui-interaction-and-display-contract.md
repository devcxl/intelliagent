# ADR 0012: TUI 交互与展示契约（pi 最小集）

## 状态

已决策，已实施（issue #87 父规格，#89/#90/#91/#92 分批落地）。修订 ADR 0009 中「单行输入框（Enter 提交）」的决策；ADR 0009 的布局骨架与 ADR 0010 的 pi 复刻方向不变。

## 背景

原 TUI 的键位与展示是未确认的隐式默认值：键位只剩 Textual 内置默认（`Ctrl+Q` 退出），引擎已有 `abort` seam 但 TUI 从不创建中止信号，运行中想停下只能杀进程；输入是单行 `Input`，多行粘贴破坏结构，运行中按 Enter 会静默变成 steer 或 follow_up；消息带「你 / 助手 / 系统」标签且为纯文本；工具面板固定折叠、结果不显示耗时；状态栏缺 token 与运行耗时；消息流不能键盘滚动，流式输出超出视口后不再跟随。

这些默认值在实现骨架时顺手选定，没有经过使用者确认。本 ADR 把交互与展示固化为显式契约，避免行为与预期继续错位。

## 决策

### 键位表（pi 日常最小集）

下表是实际绑定，语义与 `src/tui/app.py`（应用级）和 `src/tui/editor.py`（编辑器级）一致。

| 按键 | 语义 | 生效位置 |
|------|------|----------|
| `Enter` | 空闲时开始一次 run；运行中作为 steer 插入当前循环；run 已收束（`agent_end` 已发）但 worker 未回收时转走 follow_up，避免静默丢失 | 编辑器 |
| `Alt+Enter` | 运行中作为 follow_up 排队，本轮收束后执行；空闲时与 `Enter` 等价（开始 run） | 编辑器 |
| `Shift+Enter` / `Ctrl+J` | 插入换行 | 编辑器 |
| `Esc` | 置位 abort 信号并显示「中止中」；模型流在下一个流事件处尽快中止，正在执行的工具不会被打断，待工具结束后的 turn 边界收束；空闲或已收束时无副作用 | 应用 |
| `Ctrl+C` | 有选中文本时复制；输入非空时清空；输入为空时退出 | 编辑器 |
| `Ctrl+D` | 输入非空时删除光标右侧字符；输入为空时退出 | 编辑器 |
| `Ctrl+Q` | 任何时刻立即退出（Textual 默认绑定） | 应用 |
| `Ctrl+O` | 整体切换工具输出：存在折叠面板时全部展开，否则全部折叠 | 应用 |
| `PgUp` / `PgDn` | 消息流上翻/下翻一页；滚回底部恢复跟随 | 应用（priority） |
| `Ctrl+Home` / `Ctrl+End` | 跳到消息流顶部并停止跟随 / 回到最新输出并恢复跟随 | 应用（priority） |
| `Ctrl+P` / `Ctrl+N` | 浏览本次会话的提示词历史（旧/新），仅内存保留最近 100 条 | 编辑器 |

`PgUp`/`PgDn` 与 `Ctrl+Home`/`Ctrl+End` 使用 priority 绑定，编辑器聚焦时也不会被 TextArea 的整页移动消费；命令面板已关闭，`Ctrl+P` 让给历史。

### 编辑器

`TextArea` 承载多行输入，内容高度随软换行后的可视行数在 3 到 8 行之间自适应，另加一行顶部分隔线；超出 8 行后编辑器内部滚动。提交与换行在编辑器层拦截，应用层只接收「提交 + 是否排队」的消息。

### 运行编排

每次 run 创建一个线程事件作为 abort 信号，`Esc` 置位。置位后模型流在下一个流事件处尽快中止（适配器检查 abort 并产生 `Done(stop_reason="aborted")`）；正在执行的工具不会被打断，引擎在工具结束后的 turn 边界收束。运行中提交按显式意图分派：`Enter` 走 steer，`Alt+Enter` 走 follow_up；引擎已收束但 worker 尚未回收的窗口期统一走 follow_up，避免对已无消费点的 steering 队列写入。

### 消息展示

- assistant 用 Textual 的 Markdown 流式渲染（代码块高亮、列表、表格），沿用「合并到达增量、只重绘本单元」的成本约束；正文用主题前景色。
- user 与 system 为纯文本，绝不按 Markdown 解析（用户输入中的 `*` 等保持原样）；user 用 accent、system 用 warning 色。
- 三类消息都不显示角色标签，仅以颜色与结构区分。
- 空消息收束后显示占位「（无内容）」；流式错误以「（流式错误：…）」随增量落屏，不被静默吞掉。

### 工具面板

运行中自动展开，`tool_execution_end` 后自动折叠为一行摘要。标题由工具名、状态（执行中/成功/已拒绝/失败）与耗时（秒，0.01s 精度，来自 Observation 的 `duration_ms`）组成；展开正文展示参数、进度与结果，最高 20 行，超出后在面板内滚动，不把消息流顶走。

### 状态栏

单行分段显示：运行状态（运行中与收束后附带已用秒数）、模型显示名、本轮 token（`↑` 输入 / `↓` 输出，1000 及以上用 `k` 缩写）、工作目录（home 前缀缩略为 `~`）。token 在 run 内按 `MessageEnd.usage` 累计，新 run 清空；无 usage 的收束不显示该段，也不用 0 伪造。不显示时间戳，不显示上下文占用百分比。

### 消息流跟随

贴底时新内容自动滚动到底；用户上滚或 `Ctrl+Home` 后停止跟随；`Ctrl+End` 或滚动回到底部恢复跟随。翻页与跳转由应用级动作驱动，不依赖鼠标。

### 事件协议

- `MessageEnd` 增加可选字段 `usage: Usage | None`，由 `message_events` 从 LLM 流的 `Done.usage` 透传；error/aborted 等无用量收束保持 `None`。
- 无头 JSON 的 `message_end` 事件增加 `usage` 字段：`{prompt_tokens, completion_tokens, total_tokens}` 或 `null`。这是附加字段，既有字段与语义不变，向后兼容。
- TUI 状态栏只消费 `MessageEnd.usage`，不直接读取 LLM 流。

### 对 ADR 0009 的修订

ADR 0009 的「单行输入框（Enter 提交）」被本条取代：输入改为 3–8 行自适应的多行编辑器，`Enter` 仍提交，换行改由 `Shift+Enter`/`Ctrl+J` 承担。ADR 0009 的布局骨架（消息流 + 输入 + 底部状态栏、无侧栏/设置面板/主题系统）不变；ADR 0010 的 pi 复刻方向（steering/follow_up、abort 语义、事件流作协议）不变。

### 模块落点

编辑器、消息视图、工具面板、状态栏、消息流容器、应用编排各自独立模块；应用编排只保留键位表、run/abort 生命周期与事件落点。被拆分取代的旧合并组件模块已删除，不保留兼容层。

## 被否决的方案

- **可配置 keymap（keybindings.yaml）**：先稳定默认值，避免过早暴露配置面；键位可配置会让测试矩阵与文档同步成本成倍增加。
- **Claude Code 形态的斜杠命令与权限确认弹窗**：斜杠命令、命令补全与会话管理不在本次范围；权限仍由外部 permission 插件在工具流水线承载，TUI 不做第二套审批入口。
- **工具面板始终折叠或始终展开**：始终折叠看不到执行进度，始终展开会让长输出淹没消息流；运行中展开、结束后折叠是两者的折中。
- **状态栏显示上下文占用百分比**：需要 Compactor 与运行时额外接线，且投影尚未稳定；本轮 token 已足以感知消耗，避免过早耦合。

## 后果

- 交互不再依赖 Textual 默认值的偶然组合，键位、中止、排队与滚动都有显式语义和测试覆盖。
- `usage` 为附加字段，事件协议与无头 JSON 向后兼容，但无头事件断言需同步更新。
- 状态栏与工具面板的格式化逻辑各自随组件模块存放，展示改动不再牵动应用编排。

## 已知限制

- 工具执行期间无法即时打断：`Esc` 已接受后状态栏显示「中止中」直到当前工具结束并收束。
- 运行中退出不等待 run 正常收束：Textual 关闭会取消 run worker 并执行资源清理；取消路径可能仍发出 `outcome=error` 的 `agent_end`。
- `Ctrl+C` 是上下文相关键（复制/清空/退出），与部分终端或编辑器的肌肉记忆不同。
- `PgUp`/`PgDn` 被应用级 priority 绑定抢占，编辑器内不能再整页移动。
- `Shift+Enter` 依赖终端键盘协议（Textual 的 Linux 驱动默认开启 disambiguate 与 report all keys）；不支持的终端用 `Ctrl+J` 兜底，因为 `\r` 与 `\n` 在字节层就是两个键。
